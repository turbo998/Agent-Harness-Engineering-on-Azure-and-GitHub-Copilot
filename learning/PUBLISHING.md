# 学习资产入库规范

## 发布范围

发布可独立复用的技术速查、模板、POC 验收清单、架构模式、练习卡。研究流水账、原始抓取内容、内部配置、个人路径、客户身份、真实凭据、内部运行报告不发布。纯新闻或雷达条目留在研究侧，不为凑数量入库。

首次整理覆盖历史材料：保留研究快照边界，不代表重新验证历史所有事实。资产可能仍有错误或过时内容，使用前须核对官方文档、目标版本、租户及区域。证据层级必须区分官方文档、release、commit、示例、社区自述和实机验证。

## 每日流程

1. **提炼**：从当日学习中至少产出一个有独立用途的模板、检查清单、图模式或练习卡。已有内容则做有依据的增量更新，避免重复堆积。
2. **整理**：去除内部研究过程，保留公开来源、研究日期、适用范围和未验证项。跨宿主结论分别核验，不能将单一产品行为写成统一标准。
3. **核验与审查**：对当日新增的事实与来源做核验，检查敏感信息、个人路径和内部链接。运行独立审查，修复阻断问题。自动脱敏不能代替内容评审，URL 可达也不能证明事实准确。
4. **入库**：只将评审后的文件放入 `learning/assets/`。只读扫描和索引命令：
   ```bash
   python scripts/publish_learning_assets.py --index-only --dest learning
   python -m unittest discover -s scripts -p 'test_publish_learning_assets.py'
   ```
   第一条会读取现有资产、检测部分敏感格式、更新索引和本地报告；不会改写资产正文。任一命令非零即停止发布。
5. **提交**：只暂存指定资产及对应索引，检查实际 staged diff。不得批量加入其他人的未提交文件，不使用 force push，不提交本地报告或 Python 缓存。
6. **验证**：推送成功后核对远端提交与文件内容，再在每日简报提供 GitHub 文件链接和 commit 链接。仅本地落盘或仅 commit 都不能称为已入库。

## 脚本的边界

`publish_learning_assets.py --source <draft-directory> --dest <temporary-directory>` 可生成**待审草稿**；应在仓库外临时目录执行。它是规则式预处理器，不保证消除全部秘密，也不判断事实正确性、许可证或发布资格。不得对已人工整理的仓库资产执行全量覆盖或无人值守 `--force`。

`--index-only` 检出的可疑文件会从索引排除并返回非零，**不会自动从磁盘删除文件**。必须人工移出发布区并重新审查，不能在失败后继续 `git add`。

本地报告位于 `learning/.publish-local/`，受 `.gitignore` 排除。不要上传原始源目录、内部研究记录或认证配置。

## 元数据与溯源

- `catalog.json` 包含相对路径、标题、可确认的日期、主题、状态、内容 SHA-256。
- 日期仅在标题或文件名明确给出完整日期时自动提取，否则为空；不凭 mtime 或链接中的日期猜测。
- 目录中的 `published` 表示已纳入公开资产索引，不表示通过了实机或合规验证。
- 来源链接属于归属与核验线索，不代表第三方为本文结论背书；保留必要署名，不整体复制第三方代码或技能包。

## 失败与补偿

认证失败、权限不足、分支保护、非快进冲突、敏感信息、独立审查未通过：保留本地成果并在简报说明阻塞，不宣称已上传。下一次先处理遗漏的合格资产；不得绕过分支保护或强推解决冲突。若 main 禁止直接推送，提交独立分支并创建 PR，明确报告“待合并”。
