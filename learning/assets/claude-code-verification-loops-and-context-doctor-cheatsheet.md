# 编码 Agent 验证循环与上下文体检模板

> **发布界定**：由历史研究材料整理的教学模板，不是产品功能清单。本次未运行 CLI、模型或云服务，不构成生产或合规保证。此前未逐字核对的模型机制、量化收益和版本结论不收录。

## 1. 验证循环的四种挂载方式

以下是工作流设计选项，不表示任一 CLI 原生提供同名命令。

| 方式 | 如何使用 | 最小验收 |
|---|---|---|
| 手动触发 | 作者完成一轮变更后调用项目验证流程 | 保存测试命令、退出码与失败项 |
| 内嵌步骤 | 把验证放入编码任务的完成条件 | 验证失败不得报告完成 |
| 链式门禁 | 依次做需求检查、测试、独立审查 | 各阶段有输入、输出、放行条件 |
| PR 门禁 | 在 CI 中执行确定性检查，必要时加入独立审查 | 分支保护与审批不能仅靠 prompt 实现 |

## 2. 上下文体检清单

- [ ] 明确宿主实际加载的指令文件、优先级和版本。
- [ ] 将重复规则合并，删除过时配置，但保留不可妥协的安全边界。
- [ ] 按任务加载相关资料，不把完整知识库塞进每次提示。
- [ ] 明确工具参数、错误契约、超时及输出预算。
- [ ] 用固定测试集比较精简前后的质量、成本和失败模式；不预设精简一定更好。
- [ ] 把模型偏好与强制权限策略分开；是否启用自动记忆由数据与保留策略决定。

## 3. Workshop 练习卡

**输入**：一个无密钥 toy repo、一项小改动、一个刻意失败的测试。

**步骤**：生成改动 → 跑测试 → 根据失败证据修复 → 独立 reviewer 审查 → 输出完成证据。

**验收产物**：变更 diff、测试退出码、失败与修复摘要、独立审查问题清单、未完成项。

**负向测试**：让 agent 在测试失败时尝试报告成功；外层验证流程必须拒绝放行。不得把 agent 自述当作测试结果。

## 4. 使用边界

本文只给可移植的验证模式；具体技能命令、hooks、自动记忆、上下文窗口及模型收益，需查目标宿主官方文档并实测。模板没有引用未经复核的统计数字或宣称某种提示方式已经过时。
