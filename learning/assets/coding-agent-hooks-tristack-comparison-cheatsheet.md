# 编码 Agent Hooks 与权限治理对照验收模板

> **发布界定**：从历史对照研究中提取的可复用测试模板，不是当前产品支持矩阵。本次未运行任何 CLI。旧资料中“文档未提及即判定不支持”的结论已移除；需按目标版本分别验证。

## 1. 先区分三个层面

- **权限策略**：什么资源、目录、网络和工具可以访问。
- **审批机制**：哪些动作需要人工确认，自动批准的条件是什么。
- **Hooks**：执行前后能观察、拒绝或改写什么；不能假定 hook 等价于沙箱或安全边界。

命名权限档位与动态分类可以并存。是否可审计取决于实际日志、决策证据和强制执行层，不能仅根据“画像/分类器”二分判断。

## 2. 按宿主与版本填写矩阵

对 Codex、Claude Code、Mistral Vibe 或其他工具分别填表，不复用其他宿主的字段和语义。

| 检查项 | 必须记录的证据 | 最小负向测试 |
|---|---|---|
| 输入字段 | 官方 schema、实际事件 payload（脱敏） | 缺字段与错误类型 |
| 拒绝能力 | 决策字段、退出码、错误行为 | 禁止动作未被执行 |
| 参数改写 | 是否支持、适用工具、改写后的校验 | 非法参数不得绕过 schema/权限 |
| pre/post 时机 | 各事件触发点 | post 不能被当成副作用回滚 |
| 多 hook 行为 | 顺序/并发、冲突决策 | 一个 hook 拒绝时其他副作用如何处理 |
| 异常处理 | 超时、崩溃、无输出、非法 JSON | 明确 fail-open/fail-closed |
| 配置与信任 | 用户/项目层级、覆盖与目录信任 | 不可信 repo 不能静默启用执行 hook |
| 审批绑定 | 审批范围、参数、有效期 | 改写参数后必须重新评估授权 |
| 审计 | session/tool/approval ID 与时间 | 日志可复盘且不含密钥 |

## 3. Workshop 练习

使用临时目录和 mock 工具，禁止真实云资源与用户密钥。

1. 定义一项允许动作和一项禁止动作。
2. 实现或配置一个读取事件的 hook；字段以当前官方文档为准。
3. 测试正常、拒绝、超时、非法输出四种情形。
4. 若宿主支持参数改写，再验证改写后重新进行 schema 与权限校验。
5. 输出版本、配置摘要、测试结果、审批和日志证据；未验证的单元格保留“未知”。
