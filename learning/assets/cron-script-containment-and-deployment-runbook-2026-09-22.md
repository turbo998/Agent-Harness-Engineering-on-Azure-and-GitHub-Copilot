# 沙箱内定时脚本部署与验证 Runbook（2026-09-22）

> 范围：调度器限定脚本必须位于一个允许目录，并在执行前解析真实路径的场景。以下是工程模式，不保证所有调度器采用相同实现。上线前核对目标版本的 runner 和路径校验。

## 故障模型

假设版本化源文件位于 `REPO/scripts/scan.py`，允许执行目录为 `PROFILE/scripts/`。

```text
PROFILE/scripts/scan.py --symlink--> REPO/scripts/scan.py
```

直接用 Python 执行该链接可以成功，但调度器可能按以下顺序验证：

1. 将相对路径拼到允许目录。
2. 调用 `resolve()` 解析所有软链接。
3. 验证真实路径是否仍在允许目录中。
4. 通过后才选择解释器并执行。

若真实目标在允许目录外，第 3 步应拒绝。把相对路径换成相同链接的绝对路径不会改变真实目标，因此不是修复。也不要为了运行脚本禁用 containment guard。

## 正确部署

- 版本化源文件留在 repo；允许目录里部署**实体文件**。
- 在允许目录内创建临时文件，写入已审查源码，再用原子替换更新入口。
- 不沿着旧 symlink 覆盖写入，否则改的是源文件，入口仍然越界。
- 每次部署后验证入口不是 symlink、真实路径仍在允许目录、内容 SHA-256 与版本化源一致。
- 检查允许目录及其父目录的权限；该方案假设目录由受信任操作者控制，不解决恶意并发替换目录的竞态。
- 更新源文件不等于更新部署副本；把哈希比对作为每次发布的门禁，发现漂移就停止交付。

## 按边界验证，而不是按方便程度验证

| 验证层 | 断言 | 证明什么 |
|---|---|---|
| 纯函数/单元 | parser、选定 profile、失败状态 | 逻辑符合契约 |
| 文件部署 | 非 symlink、目录内、字节一致 | 部署的是正确版本 |
| 实际 script runner | runner success、summary 可解析、无 fatal/scan-error | 路径校验与子进程执行通过 |
| 完整定时任务 | 真实触发完成且消息送达 | 调度、模型、投递整条链路通过 |

前三层通过不等于最后一层已验证。若仅调用 script runner，应明确标注「采集入口已验证；下一次计划触发和消息投递尚未验证」。不要用 scheduler 的宽泛 `last_status=ok` 掩盖其采集阶段失败。

## 扫描脚本契约

- 从显式 profile 参数或宿主设置的环境变量选择根目录，不硬编码个人机器路径。
- 读取失败或根目录消失属于**采集失败**，必须非零退出，并保留诊断。
- 找到过长文档、陈旧条目等是**扫描发现**，可以用成功退出加结构化 summary 表达。
- 检测脚本只读业务资产；语法编译需要临时输出时使用系统临时目录，禁止向库里写缓存。
- 稳定输出使用 JSON 字段；由模型判断优先级，而非让模型凭记忆计算数量或决定重试。

## 最小回归矩阵

1. 允许目录中的实体文件：runner 接受。
2. 指向目录外的 symlink：runner 拒绝；相对与绝对路径都拒绝。
3. `..` 或绝对路径直接指向目录外：拒绝。
4. 完整的测试 profile：只扫描测试资产，运行前后内容不变。
5. 缺少必要根目录/记忆文件：失败，不输出「健康空库」。
6. 源和部署副本不一致：发布门禁失败。

## 依据与边界

模式依据：Python `Path.resolve()` 与真实路径包含关系、原子文件替换，以及对一个 Hermes 本地 runner 的实机复现。实机验证不代表所有版本都有完全相同的路径或调用签名；本文不分发宿主配置、标识或内部日志。

- [Python pathlib](https://docs.python.org/3/library/pathlib.html)
- [Python os.replace](https://docs.python.org/3/library/os.html#os.replace)
- [Hermes Agent 源码](https://github.com/NousResearch/hermes-agent)

执行前在所部署版本中检查实际调用方；公开项目链接不是版本固定的兼容性保证。
