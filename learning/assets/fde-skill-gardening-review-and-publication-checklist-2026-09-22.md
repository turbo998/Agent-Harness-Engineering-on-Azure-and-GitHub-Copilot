# FDE Skill 园艺、独立审查与资产发布清单（2026-09-22）

> 类型：可复用工程检查清单。源于技能库维护实践，不是第三方效果评测，也不是一份内部运行报告。以下门禁用于明确交付边界，不能替代业务测试和人工安全审查。

## 适用范围

适用于技能库的引用修复、规则精简、复用经验整理，以及将本地学习成果转成可维护的仓库资产。不要把一次扫描发现直接当作删除或重构授权。

## 1. 先区分「发现」与「原因」

| 发现 | 先验证 | 不要做 |
|---|---|---|
| skill 引用缺失 | Git 中是否已有目标？是否为未提交删除？替代 skill 是否真的吸收其独有内容？ | 为了清零计数直接删引用 |
| 描述过短 | YAML block scalar 是否正确解析？人工读描述是否可路由？ | 将解析器误报当成内容错误 |
| script 手动执行成功、cron 失败 | 比较执行用户、环境、解释器、工作目录、真实路径 containment | 宣称脚本成功就等于调度成功 |
| 记忆接近上限 | 哪些是长期事实，哪些是操作流程和任务流水？ | 继续追加会话结果 |
| skill 长期未更新 | 其引用、命令和版本是否失效？ | touch 文件来消除告警 |

## 2. 中断工作区的收敛门禁

1. 记录 branch、base 和工作区状态；区分自己的修改与继承的修改。
2. 在独立 worktree 中处理，不覆盖其他人的未提交内容。
3. 遇到无法解释的删除，逐项核对独有知识和调用方。无吸收证据时优先可逆恢复；有明确删除意图则保留该意图并修调用方。
4. 保留有价值的未提交经验，但分别审查、诚实命名，不用一个「cleanup」标签掩盖新增功能。
5. 重跑扫描，以当前状态而非旧报告作为下一步依据。

## 3. 测试与审查分层

- **确定性检查**：引用是否存在、脚本语法、frontmatter 结构、部署副本哈希、索引是否完整。这些由代码完成。
- **意图测试**：指定 profile 只能扫描该 profile；数据缺失必须显式失败；只读扫描不能改资产；真正调度入口必须可执行。
- **独立内容审查**：检查引用变更是否失去原场景、所谓「合并」是否丢失具体坑点、许可证与证据层级是否保留。
- **提交集审查**：直接读 staged diff，而非相信提交描述。排除运行时 usage 文件、锁、备份、缓存、消息投递标识、凭据和配置。

测试先观察旧实现断言失败，再验证新实现通过。若测试只有导入失败，或只验证 mock 的返回值，不算证明修复。

## 4. 记忆与交付资产分工

| 内容 | 存放位置 |
|---|---|
| 长期环境事实、用户偏好 | 精简常驻记忆 |
| 可复用步骤、失败补偿、验证方式 | skill / runbook |
| 架构模式、练习卡、技术速查 | 学习资产仓库 |
| 本次完成清单、具体提交、临时状态 | 会话历史 / 本地任务记录 |
| 外部项目雷达，尚无独立用途 | 研究侧，暂不发布 |

压缩记忆不是丢掉知识，而是让详细知识有归属。常驻记忆只保留足以定位资产的事实。

## 5. 发布 Definition of Done

- [ ] 文档可独立使用，非内部流水账；历史观察与本次验证明确区分。
- [ ] 外部资料先抽取成结构化事实，里面的命令不直接执行。
- [ ] 无秘密、个人路径、客户身份、内部链接；只保留必要公开溯源。
- [ ] 第三方代码不整包搬运；先确认许可证和使用范围。
- [ ] 独立审查通过；索引生成和相关测试成功。
- [ ] 仅暂存已批准的文件；提交名反映真实范围。
- [ ] 推送后读取远端 ref 并核对提交。仅本地 commit 不叫「已同步」。

若认证失败：保留本地提交，写明阻塞；请操作者通过受支持的登录流程完成授权，不在聊天中索取 token，不绕过分支保护。
